# Infrastructure Healing Workflow

> [!IMPORTANT]
> **Workspace Alignment**: Infrastructure healing MUST strictly operate on the master `adamic` repository (`C:\Users\chris\Desktop\wiki-search-worker`). Always ensure all log reviews, code edits, and validation commands (`pnpm run lint; pnpm run typecheck`) explicitly use `C:\Users\chris\Desktop\wiki-search-worker` as the working directory regardless of which project workspace context initiated the task.

This workflow is designed to periodically review the `agent-exec-issues.jsonl` files generated by the execution bridge, identify any recurring agent hallucinations or execution failures that are not already handled, permanently patch the `lib-agent-exec` infrastructure to heal them, and then clear the logs to maintain a pristine environment.

## 1. Review the Execution Logs

First, examine the `agent-exec-issues.jsonl` log files across the unified ecosystem to identify what agents have been struggling with:

- `C:\Users\chris\Desktop\wiki-search-worker\.agents\agent-exec-issues.jsonl`
- `C:\Users\chris\Desktop\mysql-mcp\.agents\agent-exec-issues.jsonl`
- `C:\Users\chris\Desktop\memory-journal-mcp\.agents\agent-exec-issues.jsonl`

## 2. Analyze the Issues

Filter the issues into three categories:

1. **Already Healed (Frictionless Recovery)**: Entries marked as `AUTONOMOUS_HEALING_TRIGGERED` that were successfully rewritten on the fly (e.g., `jq` routed to WSL2, or `git log` routed to `get-git-history-json.ts`). These require no further action because the infrastructure is already working.
2. **Intentional Blocks**: Explicit blocks for native commands (like `grep` without stdin, `ls`, `cat`) that force agents to use native MCP tools (`grep_search`, `list_dir`). These are working as designed and should not be "healed" by allowing them through.
3. **New Unhandled Edge Cases**: Any legitimate errors, hangs, or new hallucinations that were not seamlessly recovered or intentionally blocked. These represent gaps in our infrastructure.

## 3. Permanent Infrastructure Healing

> [!TIP]
> **Software & Dependency Installation**: As part of infrastructure healing, the agent is explicitly authorized and encouraged to install updates or common, well-known software and CLIs (e.g., `ripgrep`, `jq`, `gh`, package manager updates, system utilities) whenever doing so significantly reduces friction or resolves recurring execution failures. If installing or updating a package, tool, or CLI eliminates friction, the agent should perform the installation/update directly.

If you identified any **New Unhandled Edge Cases**, you must permanently heal the infrastructure so future agents never encounter them:

1. Read the `lib-agent-exec` skill (`C:\Users\chris\Desktop\adamic\skills\lib-agent-exec\SKILL.md`) and the local `AGENT_README.md` to understand the current interception architecture.
2. If the user provided a `/mcp-heal` prompt or similar instructions, review them.
3. Modify `C:\Users\chris\Desktop\wiki-search-worker\.agents\scripts\lib-agent-exec\interceptors\system-interceptor.ts` (or relevant interceptors) to add new heuristics, regexes, or routing rules to catch the unhandled edge cases.
4. Test the fix using the usability testing suite (`/cli-audit` or `usability/coordinator-workflow.md`).
5. Run `pnpm run lint; pnpm run typecheck` in the `adamic` repository to ensure the changes are strictly validated (**ONLY if code or infrastructure changes were made**; if no code changes were made, skip validation completely). This must strictly run lint and typecheck only, explicitly NOT run build or tests.
6. Commit the infrastructure updates and synchronize them across the ecosystem (via the `/sync-workflows` and `/sync-vendor-plugins` workflows).

If no **New Unhandled Edge Cases** were found (i.e., no code or infrastructure changes were made), skip Step 3 entirely and proceed directly to Step 4.

## 4. Clear the Logs

Once all new issues have been handled (or if the logs only contained intentional blocks and frictionless recoveries), clear the logs across the ecosystem to provide a clean slate for the next phase of testing:

```pwsh
Clear-Content -Path "C:\Users\chris\Desktop\wiki-search-worker\.agents\agent-exec-issues.jsonl", "C:\Users\chris\Desktop\mysql-mcp\.agents\agent-exec-issues.jsonl", "C:\Users\chris\Desktop\memory-journal-mcp\.agents\agent-exec-issues.jsonl"
```
